# Contributing to GulfDocs

1. Read `AGENTS.md`, the relevant nested guidance, and `IMPLEMENTATION_STATUS.md`.
2. Keep the private sibling specification and learning guide outside the repository.
3. Create focused changes on the existing feature branch and use conventional commit messages.
4. Preserve adapter boundaries and authorization; do not bypass workspace checks for local convenience.
5. Add meaningful tests and run formatting, lint, type checking, unit tests, and the applicable build/E2E checks.
6. Never commit secrets, real customer documents, invented metrics, or unverified deployment claims.

Use synthetic organizations and people in fixtures. Report actual failures and limitations honestly.
